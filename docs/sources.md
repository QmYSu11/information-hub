## 官方行情组件

看盘页使用 TradingView 官方的 advanced-chart、symbol-info、technical-analysis、financials 与 symbol-profile 嵌入组件；当前标的由本站自选统一控制，主图与研究面板保持一致。浏览器直接从来源加载数据，本站不从跨域组件中提取报价到公开快照。

本次已在浏览器看到 NVDA 一分钟价格曲线、均线、成交量与延迟标记，以及摘要中的报价、市值和 EPS；此前已确认 AAPL 图表可显示实际数据。A 股样例格力电器在来源中明确只支持日/周/月，摘要为昨收等日终字段。不能将美股分钟图表成功外推为所有 A 股都有盘中分钟线。

股票更新受交易所再分发授权限制，通常为延迟行情；分钟线粒度不代表无延迟。TradingView 的[官方数据 FAQ](https://www.tradingview.com/widget-docs/faq/data/)说明了组件数据权限与实时性边界。网络、地区、标的和来源权限会影响嵌入显示，组件自己的 D 标记、报价时间和市场状态优先。

本地标的目录用于名称/代码查找，不是实时证券主数据；自定义代码仅通过格式校验，实际存在性与可用性由来源组件验证。指数跟踪 CFD、场外现货参考与连续期货在目录中注明各自含义，不能视为同一市场的成交报价。具体操作见 [自选看盘](market-desk.md)。

## 小红书推荐适配

免费优先使用 [SandBase 首页推荐](https://www.sandbase.ai/apis/xiaohongshu/web-v3/homefeed)：POST `https://api.sandbase.ai/v1/api/xiaohongshu/web-v3/homefeed`，密钥由 GitHub Actions Secret `SANDBASE_API_KEY` 提供。只配置 `TIKHUB_API_KEY` 时使用 TikHub 备用接口。密钥不进入前端、公开快照或日志。

SandBase 产品页在本次核实时标注组织每天前 100 次调用免费，UTC 00:00 重置，超出后收费；实际资格、共享额度与规则以账户页面为准。本站同一服务最多每小时尝试一次，单次最多一页 20 条，失败也冷却一小时，不自动翻页、不隐式重试。

当前未配置服务密钥，所以尚未采集到真实推荐帖子。规则测试使用本地样例，不把文档示例当作实时内容。配置后只保存公开卡片元数据与来源确实提供的时间；失败保留上次成功内容与原时间。完整注册、Secret 配置和验证范围见 [小红书接入说明](xiaohongshu.md)。

## 行情的可选适配

scripts/quotes.mjs 内含腾讯报价适配，默认不运行。启用前需要自行确认服务使用范围与公开展示许可，不能仅以接口可访问为依据。

本地仅在明确需要时设置 ENABLE_TENCENT_QUOTES=true 再运行采集；GitHub 通过仓库 Variables 中的同名变量控制，默认留空。不要将任何私人密钥写入前端。未启用时明确显示“在来源组件中查看；本站未保存报价”。

适配范围：上证、深证、标普 500、纳斯达克综合、苹果、微软、伦敦金现货。未加入商品期货连续合约，避免在没有合约月份和单位验证时误报。有效采集时也标记“延迟情况未知”；未取得连续历史时不绘制自造走势图。

A 股时间按 Asia/Shanghai、美国证券时间按 America/New_York 转换，夏令时使用时区数据库处理；黄金报价时间未独立核实，故不将抓取时间冒充报价时间。此适配只是可选能力，默认版本不能被描述为“已自动采集全部市场行情”。

## 更新、缓存与时间语义

默认工作流每小时第 7、37 分钟计划运行，避开整点拥堵。GitHub 任务可能延迟，不能承诺严格每半小时更新；公开仓库长期无活动时计划任务可能停用。可从 Actions 手动执行。

每个来源独立获取，限时 18 秒；失败保留该来源上次条目及原 fetchedAt、lastSuccessAt，只记录新的 lastAttemptAt 和失败状态。某个来源失败不抹掉其他源。全部新闻与热榜均失败时任务以非零状态退出，保留已发布网站，不发布空站点。小红书额外采用上述一小时调用冷却，未配置密钥时不发送请求。

generatedAt 仅指这代快照的生成时间，不代表每篇报道的发布时间或每个来源的成功时间。缺少 pubDate 的条目不填写 publishedAt。前端应根据 lastSuccessAt、条目时间及当前时间展示缓存/过期状态。

最近快照持久化在独立 data 分支，只有 snapshot.json，不包含笔记、待办、偏好、游戏存档。源码 main/master 分支和数据分支不互相覆盖，data 分支变更不触发新的源码发布循环。快照使用完整构建产物发布，避免读到半份 JSON。

该分支只保留当前所需条目，不做全量媒体归档。Git 历史仍会随更新增长，长期使用可按自身维护策略归档或更换快照存储。

## 验证与维护

- npm test 验证：去重与链接安全、富文本清理、失败缓存时间、B 站 ID 与排名、公开快照禁止个人字段、美国夏冬时区、无效报价保持 null。
- node scripts/verify-snapshot-state.mjs 独立验证 data 分支保存与恢复，仅操作自行创建的临时测试仓库，需要环境允许 Git 写入；已在有相应权限的本地环境通过，CI 也会运行。
- npm run collect 进行真实网络验证；不在单元测试中反复请求来源。
- npm run build 检查类型与静态构建。上线后另行检查所在网络是否能加载原文、图片与官方播放器。
- 来源格式变化时先修复对应适配器，不让未经验证的字段直接进入站点。不要将“采集成功但全是旧文章”当作内容刚刚发布。
