# 网站开发准备清单

日期：2026 年 11 月 11 日  
配套文档：requirements.zh-CN.md  
范围：开发准备，不包含已实现网站或已验证数据接口的声明。

## 1. 开工基线

- 免费优先，源码放 GitHub，网站通过 GitHub Pages 发布。
- 前端建议 React + TypeScript + Vite，构建输出静态文件。
- IndexedDB 保存个人数据，Dexie 为可选访问层；不默认启用云服务。
- GitHub Actions 计划采集与构建公开快照，默认 30 分钟一次，受来源额度与实际调度影响。
- 页面只读取快照，不携带服务密钥，不使用用户平台登录 Cookie 作为接入基础。
- 先实现信息门户；游戏代码和资源独立加载。
- 具体依赖版本在开工时核实，使用受支持的稳定版本与锁文件。

## 3. 第一批设计样稿

| 样稿 | 必须表达的行为 |
| --- | --- |
| 今日桌面页 | 新闻为主、热榜与财经为辅、待办只占少量空间 |
| 今日手机页 | 单列与清楚入口，不卡片横向滑动才能读标题 |
| 专注阅读 | 字号/宽度可调，来源与原文入口明确，关闭后回到原位 |
| 影院模式 | 播放与加载状态、可识别的嵌入错误、加载等待提示；始终保留原站入口和用户主动“无法播放”入口 |
| 热榜页 | 榜单类型、抓取时间、原始热度和来源状态 |
| 笔记页 | 列表与编辑器、来源引用、自动保存与失败草稿 |

样稿数据仅用于验证布局，必须标记“演示内容”；正式验收使用通过验证的真实数据。

## 4. 来源验证记录模板

每个来源建立一条记录：

| 字段 | 内容 |
| --- | --- |
| 来源与官网 | 官方身份、数据提供者、文档链接 |
| 覆盖类型 | 新闻、榜单、行情、正文、播放器等 |
| 访问条件 | 无账户、开发密钥、审批、收费等 |
| 公开展示范围 | 元数据、摘要、图片、正文、行情快照分别确认 |
| 实际样例 | 成功时间、HTTP 状态、字段、缺失值、内容时间 |
| 刷新预算 | 每次请求数、每天预算、计划频率、超限回退 |
| 访问环境 | 任务采集环境能否连接；用户浏览器能否打开原站/播放器 |
| 跨域情况 | 若计划浏览器直连，单独验证；任务侧请求不等于浏览器可直连 |
| 稳定性 | 连续多个周期的结果、超时与错误响应 |
| 展示能力 | 正文、摘要、嵌入、仅原站；不能根据类型自行推断 |
| 失败策略 | 最近成功快照、过期阈值、原站地址 |
| 验证结论 | 可接入、需账户/审批、需改方案、仅原站、暂缓 |

优先次序：国内新闻、国际新闻、B 站播放、三个指定平台榜单、财经新闻、分市场行情。

核心门户验收至少需要一个指定平台的真实自动更新热榜，不能用全部外链代替。行情按 A 股、美股、大宗商品分别记录可用报价和延迟，未接入项只能标记暂缓。来源验证必须优先判断这些最低范围在免费方案下是否可达。

对于需要开发账户的免费源，先完成无需账户的适配与完整样例，再让用户按说明在对应服务自行申请。私钥只进入任务密钥配置。

## 5. 数据契约与展示状态

每个公开快照包含结构版本、generationId、生成时间、来源状态与条目列表。时间统一保留 UTC 与必要的市场时区信息，展示时转换；不将采集时间当作发布时间。

建议来源状态：正常、获取中、获取失败但有缓存、已过期、无数据、未配置、仅原站入口。状态有独立含义，不能全部显示成“暂无内容”。

建议初始过期阈值：

- 新闻与热榜：距最后成功获取超过约 2 小时，显示“更新延迟”；超过 24 小时明显标记历史缓存。
- 行情：按实际源的频率、延迟和交易日历定义；休市不按开盘期间的阈值误报故障。
- 条目的发布时间与快照获取新鲜度分别判断。刚抓取到旧文章仍然是旧文章。

实际阈值在来源验证后调整，不能用阈值掩盖没有新数据。

## 6. 构建与刷新工作流设计

代码更新与计划采集最终都走同一发布流程，使用部署互斥，避免相互覆盖。

1. 获取默认分支最新代码和最近可用公开快照。
2. 按来源调用频率采集，配置超时与有限重试。
3. 校验结构、时间、URL 和展示权限，清理富文本。
4. 成功源替换自身快照；失败源保留旧快照和原 lastSuccessAt。
5. 生成完整的新一代 JSON，限制条目数量与历史体积。
6. 保存允许公开的最近快照到受控数据分支，确保下次任务可恢复。
7. 运行构建与必要检查，发布完整 Pages 产物。
8. 无任何成功更新时避免误报“数据已刷新”，保留可用站点并记录失败。

采集记录中不输出密钥、完整认证头或私人数据。定时采集失败不能清空已发布站点。

不要将需要频繁触发的动态接口直接写进浏览器，也不要使用公开的仓库写入凭证，让所有访问者都能触发高成本任务。

## 7. 页面刷新与静态路由

初期使用兼容 Pages 的 hash 路由，降低项目子路径和深层链接刷新失败的风险。静态资源路径按仓库 base 配置，不能把所有资源写成网站根路径。

书签与分享链接不带个人笔记正文、密钥或私人待办内容。详情链接失效时，提供返回列表与原站入口。

PWA 后置：先通过普通部署验收，再增加缓存与安装功能。Service Worker 的数据缓存不能让过期新闻或行情被永久固定；升级时不强制刷新并丢弃未保存的笔记。

## 8. 本地数据库与备份

先设计稳定 ID、索引、schemaVersion 与迁移策略，再编写编辑器。个人资料、公共缓存和游戏存档使用独立表及独立清理规则。

完整备份包括 notes、folders、tags、savedItems、reminders、preferences、watchlist 与 gameSaves。导出文件包含版本、导出时间和数据计数；导入校验版本、类型、重复 ID 和引用关系。

备份为用户本机文件，默认未加密，在导出界面简洁说明保存位置由用户自行选择。未来如需本地加密，单独设计密码与恢复方案。

## 9. 按顺序的实施待办

1. 验证真实来源，完成能力矩阵与样例。
2. 定义组件、深浅主题、字号、动效和响应式规则。
3. 完成今日、新闻、热榜、财经新闻与来源状态。
4. 完成专注阅读、影院、原站回退；第三方播放器内部状态不可读时不推测错误原因。
5. 完成收藏、稍后读、位置恢复、列表筛选与本地搜索。
6. 打通采集与 GitHub Pages 发布，使用真实快照完成一次日用流程。
7. 完成本地笔记、标签、草稿恢复与备份导入导出。
8. 完成提醒、重复实例去重、到期补查和可选系统通知。
9. 分市场完善行情、自选和支持的历史图表。
10. 制作游戏小样，验证自动战斗与三选一的乐趣，再扩成完整单局。
11. 完成游戏存档、局外成长、离线收益和性能隔离。
12. 根据实际问题决定是否增加 PWA、云同步和后台推送。

## 10. 验证策略

先验证最容易造成真实损失或误导的部分：数据时间、去重、过期状态、笔记存储与恢复、重复提醒、离线收益防重复结算。

组件和样式的轻微可逆修改用构建与实际预览检查即可；不编写只重复实现细节的测试。核心规则使用小而有意义的测试样例，例如相同链接不同追踪参数去重、跨午夜重复提醒、存储迁移失败保留旧数据。

每个里程碑做一次真实浏览流程与手机布局检查，记录已通过、未覆盖、来源限制。没有实际运行的项目不宣称“已测试完成”。
