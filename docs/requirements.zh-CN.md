# 个人信息门户网站详细需求报告

版本：V1.0 需求基线  
编写日期：2026 年 11 月 11 日，Asia/Shanghai  
项目暂名：信息书房（可在视觉设计阶段改名）  
当前阶段：需求设计与开发准备，尚未编写或发布网站  
已确认偏好：免费优先，可以接受部分热榜使用原站入口、行情存在延迟。

## 1. 产品定位与目标

建设一个每天愿意打开的个人信息桌面，将国内外新闻、趣事、社交平台热榜和财经信息放在统一界面中。用户可以快速扫读，也可以进入安静的阅读和观看空间，把有价值的内容保存为笔记或待办，休息时进入独立的挂机肉鸽小游戏。

新闻、热榜和财经是主产品。建议将约 75% 的主要界面与开发投入留给信息获取，约 15% 留给笔记提醒，约 10% 留给休闲入口；这是规划比例，不是锁定的工作量估算。

主要目标：

1. 减少每天在多个新闻网站与应用之间来回切换。
2. 每条信息可追溯来源，并能看懂它有多新、是否可站内观看。
3. 长时间浏览时稳定、清楚、少打扰，返回后能继续原来的位置。
4. 从阅读到收藏、笔记、提醒形成完整流程。
5. 网站代码可存放于 GitHub，并通过 GitHub Pages 访问。
6. 免费版本独立可用，为后续数据服务、同步和后台提醒保留扩展空间。

不纳入第一版：多人协作、商业订阅、站内社交评论、交易下单、全网搜索、全量视频搬运、实时交易终端和联网游戏排行。

## 3. 必须写清的能力边界

### 3.1 GitHub 上传与可访问的关系

上传源代码后，还需配置构建与 Pages 发布。项目网站通常位于“用户名.github.io/仓库名/”。GitHub Pages 托管静态页面，不提供常驻应用服务器，因此服务器定时任务、保密接口代理和云端数据库需要其他执行环境。本项目免费基线采用静态前端与 GitHub Actions 定时生成公开数据快照。[GitHub Pages 官方说明](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)

第一版网站入口通常公开可访问。笔记只保存在当前浏览器，不会因为代码上传而自动上传；这也不代表网站具有账户隔离或本地加密能力。不可将个人笔记、提醒、私有密钥或游戏私有存档打包进公开网站。

### 3.2 “实时”的产品定义

免费版采用“定时获取、展示最新可用信息”。默认计划每 30 分钟采集一次可用新闻和热榜；经过额度与稳定性验证后，可对部分来源缩短到 15 分钟。这个频率是采集计划，不是内容新鲜度保证。

网页在前台时，每隔约 5 分钟检查一次已发布快照。有新内容时显示提示，由用户决定插入。点击刷新只获取最新已发布快照，不会凭空触发实时采集。

GitHub Actions 定时任务可能延迟或丢弃；公开仓库长期无活动还可能停用定时工作流。因此网站必须显示实际采集时间和过期状态，并提供维护说明。[GitHub Actions 定时事件说明](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule)

若未来必须秒级新闻或行情，需要另行接入有相应能力的数据服务与后台推送。

### 3.3 观看能力按来源区分

统一设计三种展示能力：

| 能力 | 用户看到什么 | 适用条件 |
| --- | --- | --- |
| 站内正文 | 专注阅读页内查看正文 | 来源实际提供正文且允许展示 |
| 站内嵌入 | 影院模式、播放器或受支持的帖子组件 | 平台提供并允许嵌入 |
| 摘要与原站 | 标题、可用摘要、来源和“打开原文” | 仅有元数据、受登录限制或不支持嵌入 |

B 站官方有外链播放器，可作为站内视频体验的首选；是否能播放具体视频仍需实际验证。官方播放器的存在不能证明排行榜数据接口可用，也不意味着网页能自由控制播放器内部功能。[B 站外链播放器文档](https://player.bilibili.com/)

微博与小红书的全量帖子、评论、视频和热榜接口，当前未完成公开授权与实际可用性验证。报告不承诺所有内容站内播放或完整复刻。

## 4. 主要使用场景

| 场景 | 用户流程 | 预期结果 |
| --- | --- | --- |
| 早间快速了解 | 打开今日 → 扫读要闻 → 查看平台热榜与财经概览 | 几分钟内知道今天发生了什么 |
| 深度阅读 | 筛选国际或国内 → 打开内容 → 进入专注模式 | 阅读清晰，来源明确，返回位置保留 |
| 看热门视频 | B 站榜单 → 选择视频 → 影院模式 | 能嵌入则站内看，失败可直接回原站 |
| 保存信息 | 收藏或稍后读 → 添加个人想法 → 生成关联笔记 | 原标题、链接和来源自动附带 |
| 记录待办 | 在笔记或提醒中心设置时间 → 到期处理 | 页面内提示，遗漏事项重开后可见 |
| 跟踪市场 | 财经 → 自选关注 → 查看相关新闻与可用行情 | 看懂市场、币种、价格时间及延迟 |
| 短暂休息 | 游戏 → 自动战斗 → 选择升级 → 结算 | 不需频繁操作，离开后主站流畅 |

## 5. 信息架构

桌面主导航建议为：今日、新闻、热榜、财经、笔记、游戏。提醒中心可从今日侧栏和笔记区进入，收藏、稍后读与设置为固定辅助入口。

| 页面 | 核心内容 |
| --- | --- |
| 今日 | 今日要闻、订阅频道更新、热榜预览、财经快讯、少量待办 |
| 新闻 | 国内、国际、社会、科技、商业、文化与趣事等频道 |
| 热榜 | B 站、微博、小红书独立平台页；切换榜单类型 |
| 财经 | 财经新闻、A 股、美股、大宗商品、自选关注 |
| 内容详情 | 阅读模式、视频影院或摘要原站模式 |
| 我的收藏 | 收藏、稍后读、已读历史；可创建关联笔记 |
| 笔记 | 笔记列表、标签、编辑器、回收站 |
| 提醒 | 今天、即将到期、已逾期、已完成 |
| 游戏 | 单局远征、局外成长、存档与设置 |
| 设置 | 主题、字体、动效、来源、通知、本地数据与备份 |

手机主导航收敛为“今日、热榜、财经、笔记、更多”，新闻频道从今日进入，游戏放入更多。首页默认不运行游戏，也不出现持续滚动的装饰信息条。

## 6. 新闻与信息聚合需求

### 6.1 内容与列表

必须支持国内、国际、财经和趣事入口，后续按真实来源逐步细分科技、数码、文化、生活等频道。趣事按编辑分类或来源栏目归类，不伪造独立的“趣事热度榜”。

新闻条目包含：标题、来源、原文链接、发布时间、最近成功获取时间、频道、原始语言、可用摘要和可用图片。缺少字段时明确省略，不生成虚假作者、摘要或图片。

主要操作：

- 按来源、频道、发布时间筛选；默认按时间排序。
- 热门排序仅在来源提供可靠指标时启用，并解释指标范围。
- 收藏、稍后读、已读与未读状态。
- 屏蔽关键词或来源，可撤销和管理屏蔽规则。
- 搜索当前快照、已缓存内容、收藏和笔记；清楚说明搜索范围。
- 手动刷新；显示更新中、无新增、失败和缓存状态。
- 返回列表恢复筛选、已加载内容和滚动位置。

### 6.2 去重与持续浏览

同一来源先按稳定 ID 和规范化链接去重。跨来源同一事件可以在后续版本聚合成“相关报道”，但保留来源，不将观点不同的报道误合并为同一篇。

阅读过程中刷新只提示“发现新内容”。用户主动插入后再更新列表；不让新闻突然顶开正在阅读的条目。图片预留尺寸，长列表按需要分段加载，避免无限堆积。

### 6.3 国际信息

默认展示原始语言；已有来源官方中文内容时可优先使用。机器翻译和 AI 摘要列为后续可选功能，需要明确标记、费用来源与内容处理范围，不默认为免费版基础依赖。

## 7. 各平台热榜需求

| 平台 | 需要的榜单 | 第一版展示方式 | 依赖与回退 |
| --- | --- | --- | --- |
| B 站 | 综合排行榜、热门视频；有稳定来源后增加分区 | 排名、标题、UP 主、封面、可用指标、原链接；可用时站内播放 | 榜单获取与播放器分别验证；无可用榜单源时显示原站入口 |
| 微博 | 实时热搜类榜单 | 排名、话题、平台原始热度、采集时间；新上榜或升降仅在可比较时展示 | 未验证授权接口前使用原站入口，不用假榜单填充 |
| 小红书 | 来源明确的热搜或热点榜 | 关键词或帖子标题、来源、排名、采集时间、原链接 | 区分热搜、创作热点与商业榜单；不可冒充同一榜单 |

通用规则：

1. 热榜平台之间不比较原始热度大小。
2. “上升 5 名”等变化只比较同平台、同榜单、同口径且相邻有效快照。
3. 首次采集、不足两次有效快照或历史过期时，不展示排名变化。
4. 只在来源明确标注时保留广告或推广标签；不把未知条目认定为广告。
5. 列表支持收藏、打开原文、添加笔记和关键词屏蔽。
6. 抓取失败保留最近成功数据，显示时间；无历史数据则显示暂无数据和原站入口。
7. 外链入口是可用的降级方式，不计作“已完成自动热榜接入”。

## 8. 财经新闻、行情与自选

### 8.1 财经信息范围

- A 股：市场新闻、政策、行业与公司动态；可用时展示主要指数和自选个股行情。
- 美股：宏观与公司新闻；可用时展示主要指数、自选个股及盘前盘后状态。
- 大宗商品：黄金、白银、原油、铜等相关新闻；行情必须区分现货、期货及具体合约。
- 宏观财经：利率、通胀、汇率和重要经济事件；经济日历在有可靠来源后加入。

财经新闻在第一轮核心版本交付；具体行情按来源可用性逐项交付，不以一个“市场”页冒充已覆盖全部市场。

### 8.2 行情必备字段

名称、代码、资产类型、交易所或市场、币种、单位、价格、涨跌额或涨跌幅、价格对应时间、抓取时间、数据来源、延迟属性、交易状态。

未知延迟显示“延迟情况未知”；缺失价格使用“暂无报价”，不得显示 0。休市、历史收盘价、获取失败、数据过期应分别展示。美股夏令时采用交易所时区处理，不固定写死北京时间开盘点。

商品报价要显示例如“美元/盎司”“美元/桶”和合约月份；不能将黄金现货、黄金期货与相关股票混在同一报价卡片里。

### 8.3 自选与图表

用户可添加、删除和排序支持的关注标的。第一版关注列表保存在本地；没有报价源的标的仍可保留官方信息入口和关联新闻。

先做清楚的数字与小趋势图，日线历史图在取得足够连续数据后增加。缺失历史时不绘制虚构走势。高级技术指标、全量逐笔数据和交易下单不在本期。

### 8.4 免费数据策略

优先使用明确允许本项目用途的免费源。Twelve Data 可作为候选调研对象，是否覆盖特定市场、额度、延迟与公开展示许可必须逐项核对，不能仅凭“有免费计划”认定能同时覆盖 A 股、美股和商品。[Twelve Data 官方方案页](https://twelvedata.com/pricing)

如果免费源只允许个人使用而不允许公开再分发，就不能将行情做成公开 Pages 快照；此时采用原站入口，或在后续增加满足权限要求的账户服务。

## 9. UI、动效与沉浸体验

### 9.1 视觉方向

采用“现代编辑式阅读工具”的视觉语言：稳定的布局、清楚的文字层级、克制的强调色和适度的信息密度。首页主要呈现新闻内容，避免大幅欢迎海报挤占信息。

建议设计基线：

| 项目 | 建议 |
| --- | --- |
| 深色模式 | 低饱和炭灰背景、分层面板、柔和高对比正文 |
| 浅色模式 | 接近白色的阅读背景、明确分隔与正文层级 |
| 强调色 | 青绿色系作为初始方向，最终以可读性验证为准 |
| 字体 | 优先系统中文字体，避免首次加载大型外部中文字库 |
| 阅读正文 | 默认约 18px，可调至 16–24px；行高约 1.7–1.9 |
| 阅读宽度 | 默认约 680–760px，可切换窄、标准、宽 |
| 组件 | 一套按钮、输入框、列表、标签、弹层和状态组件 |
| 圆角与留白 | 统一尺度；以空间和层级组织内容，不将每条新闻做成厚重卡片 |

### 9.2 三种体验

浏览模式用于快速扫读，支持紧凑与舒适密度；专注阅读模式弱化导航，提供字号、宽度、目录（正文实际有结构时）、进度及原文入口；影院模式放大内容、收起外围信息，在能力允许时提供全屏。

第三方 iframe 内部播放进度、清晰度、倍速、弹幕或自动连播是否可控，取决于平台接口。第一版只承诺可验证的功能，不伪造控制按钮。

### 9.3 “丝滑”的验收含义

- 按钮和切换在本地快速反馈；网络等待单独显示。
- 过渡建议 150–250 毫秒，用于状态变化与空间关系，避免持续漂浮和无意义动画。
- 不强制自定义滚动条行为，不劫持正常页面滚动。
- 切换路由、打开关闭详情后保留合理上下文。
- 不默认有声自动播放；视频由用户主动启动。
- 识别系统“减少动态效果”，同时提供站内关闭动效选项。
- 能检测到嵌入错误时显示具体原因；无法读取第三方播放器内部状态时，只提示加载等待或可能受限，不猜测错误原因。始终保留原站按钮，并提供用户主动选择的“无法播放”入口。

### 9.4 响应式与无障碍

以 390px 手机、768px 平板、1440px 桌面为代表布局验证点，覆盖更小屏幕时主界面不横向溢出。所有主要操作可用键盘；弹层支持 Escape、焦点进入与返回；图标按钮有可读名称；涨跌不能仅用红绿颜色区分。

## 10. 笔记管理

基础功能：新建、编辑、删除、标签、单层文件夹、置顶、搜索、回收站、导出和恢复。第一版采用 Markdown 编辑与预览，后续再考虑复杂富文本、双向链接和知识图谱。

从信息创建笔记时自动附带原标题、来源、原链接、内容发布时间（如有）与记录时间；只摘录实际允许保存的内容，个人想法独立存放。原文删除后，笔记中的用户文字与引用信息仍保留。

保存要求：

1. 停止输入约 1 秒后保存，离开编辑页前进行补存。
2. 明确显示“保存中、已保存到此浏览器、保存失败”。
3. 写入失败保留当前草稿并提供导出，不能误报成功。
4. 本地数据库升级提供迁移与失败回退，不直接清空用户资料。
5. 多标签页同时编辑时避免静默覆盖，提示冲突并保留副本。

数据备份：完整 JSON 导入导出覆盖笔记、标签、收藏、待办、自选和游戏存档，携带版本号；笔记另提供 Markdown 导出。导入先预览数量和版本，默认合并并按稳定 ID 去重，覆盖恢复需明确操作。

本地保存不等于永久备份。更换设备、浏览器、站点域名或清除站点数据可能无法直接读取原数据；提供备份入口与最近导出时间。浏览器配额和自动清理规则也会影响持久化。[浏览器存储配额与清理说明](https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria)

第一版不承诺多设备自动同步，也不将 GitHub 仓库当作个人笔记云盘。

## 11. 记事提醒

提醒包含标题、备注、关联笔记或信息、到期时间、时区、重复规则、完成状态和稍后提醒。

第一版支持：

- 单次、每日、每周、周一至周五重复。周一至周五不等于中国法定工作日，暂不处理调休。
- 今天、即将到期、已逾期、已完成视图。
- 完成、编辑、取消、延后 10 分钟、1 小时或自定义时间。
- 页面前台运行时检查到期事项；切回网页时立即补查。
- 重开网站将遗漏事项汇总显示，避免一次弹出大量旧通知。
- 通过提醒实例 ID 去重，避免多标签页重复弹出。
- 导出日历文件作为免费补充路径；实际通知由导入的日历应用负责。

能力分层：

| 情况 | 免费静态版的承诺 |
| --- | --- |
| 网页处于前台 | 站内到期提示；设备休眠期间无法按时执行 |
| 标签页在后台 | 尝试通知；浏览器节流、权限与系统策略可能延迟 |
| 网页已关闭 | 不承诺准点提醒；重新进入时汇总遗漏事项 |
| 后续后台推送版 | 增加定时服务、推送订阅和账户权限，并验证各设备可达性 |

浏览器通知需要支持与用户授权；Service Worker 不是常驻闹钟。Web Push 涉及推送订阅与消息服务，不能仅靠静态网页定时器实现关闭网页后的可靠提醒。[Notifications API](https://developer.mozilla.org/en-US/docs/Web/API/Notifications_API)、[Push API](https://developer.mozilla.org/en-US/docs/Web/API/Push_API)

## 12. 网页挂机肉鸽小游戏

### 12.1 玩法定位

暂名“信号远征”：轻科幻自动战斗游戏。角色自动攻击与移动，玩家主要选择技能、装备和路线。随机事件和构筑差异提供肉鸽体验，局外少量永久成长提供持续目标。

建议单局在线体验约 8–15 分钟，允许自动选择升级，适合看完资讯后短暂游玩。时长是设计目标，需要小样验证。

### 12.2 最小完整玩法

开始远征 → 自动战斗 → 获得经验 → 三选一强化 → 战斗与事件 → 精英或 Boss → 胜利或失败 → 结算资源 → 永久成长 → 再次远征。

第一版范围建议：

- 1 个角色、1 套视觉场景，3 个随机事件类型。
- 普通敌人、精英和 Boss；清楚可辨的伤害与状态反馈。
- 约 12 个基础强化选项，支持攻速、范围、护盾、持续伤害等不同组合。
- 至少 3 种能明显感受到差异的构筑路线。
- 路线或事件选择、少量永久升级、单局统计。
- 三选一默认等待用户选择，可开启按偏好自动选择。
- 音效独立开关，默认静音；可降低画质和粒子数量。

第一版不加入多人、交易、付费抽卡和全服排行榜。

### 12.3 挂机与离线定义

进入游戏页时运行战斗；离开后停止画面渲染，隐藏标签页降低或暂停实时模拟。返回时根据保存的时间差补算。

离线只结算受上限限制的基础资源，建议上限 8 小时；不自动替用户进行三选一、跨越 Boss 或编造离线完整战斗。这样能保持挂机收益，同时保留局内选择意义。

每次升级、阶段结算和定期检查点保存。离线结算采用一次性领取标记并更新领取时间，重复刷新不能重复领同一时段收益。单机本地版本不承诺防止用户修改系统时间或存档。

### 12.4 与主站的关系

游戏资源只在首次进入游戏时加载；不占新闻首屏下载与渲染预算。离开游戏页停止渲染循环和音频，阅读页不展示战斗浮窗。游戏失败或存档异常不影响新闻、笔记和提醒。

## 14. 免费优先技术与部署方案

### 14.1 推荐结构

GitHub 仓库保存网站源码和公开配置；GitHub Actions 在构建或计划任务中获取获准来源，清洗后产生有版本号的公开 JSON 快照；静态页面与快照一起发布到 Pages。浏览器按来源读取快照，本地数据库保存个人数据。

建议前端采用 React、TypeScript 与 Vite；本地数据使用 IndexedDB，可用 Dexie 简化访问；首版不增加应用服务器、云同步或 AI 服务。具体依赖版本在开工时选择仍受支持的稳定版本并锁定。

Vite 官方有 Pages 部署说明，项目路径需要匹配仓库子路径；部署的是构建结果，不是直接让浏览器运行源文件。[Vite 静态部署说明](https://vite.dev/guide/static-deploy.html#github-pages)、[Dexie 官方资料](https://dexie.org/)

### 14.2 数据刷新与发布一致性

来源并行采集、各自限时；单源失败不阻止其他源更新。每个源独立保存最近成功快照，整体快照带 generationId。构建产生完整发布产物，再原子切换发布，避免首页代码与数据版本错配。

最近成功数据需要跨任务保留，不能依赖一次性任务文件系统。可在仓库独立数据分支保存受限的公开快照；只保留最近快照和少量排名比较历史，不保存所有全文或无限归档。

代码发布和定时数据发布使用同一部署互斥机制，避免旧构建覆盖新代码。无需在每次读取快照时重建网站；只有产生新一轮可发布数据时触发数据发布。

### 14.3 本地数据与缓存

个人记录与公共新闻缓存分开存储、分开清理。清除新闻缓存不能删除笔记、待办或存档；清除个人数据需要明确范围与二次操作。

先实现联网可用和基础缓存，再增加安装到桌面的 PWA 能力。离线时显示已保存笔记、收藏与缓存新闻，并明确“离线内容”；不能让旧行情看起来仍在实时更新。

### 14.4 密钥和输入处理

需要保密的服务密钥仅放在仓库的任务密钥配置中，不写入前端、公开 JSON 或日志。前端环境变量会进入构建结果，不能用来保密。

外部 HTML、RSS 富文本和笔记预览需清理，链接限制为允许的协议，导入文件校验格式与大小，防止外部内容在笔记页执行脚本。不开放任意 URL 的服务器抓取代理。

## 16. 性能、可靠性与验收

下列数字是设计目标，尚无网站实现可供测量。验收时记录设备、浏览器、网络、内容数量与样本，分别报告本地表现和部署后的真实网络表现。

| 维度 | 目标与验证方法 |
| --- | --- |
| 首屏体验 | 在约定的普通手机与网络条件下，以 LCP ≤ 2.5 秒、CLS ≤ 0.1 为目标；外部视频不计入主界面首屏资源 |
| 交互 | 常用操作立即本地反馈，目标约 100 毫秒内可感知；整体 INP 目标 ≤ 200 毫秒 |
| 列表稳定 | 新内容不主动顶开当前条目；返回详情后位置、筛选保留 |
| 长时间使用 | 浏览与编辑持续 30 分钟，无明显持续增长的内存、重复轮询或重复事件处理 |
| 游戏隔离 | 未进入游戏不下载其主要资源；离开后无持续战斗渲染和音频 |
| 数据真实性 | 每源可见实际最近成功时间；演示、缓存、延迟、未知时间清楚区分 |
| 存储恢复 | 导出、清理测试数据、再导入后，记录数量、正文、标签和关联关系一致 |
| 异常恢复 | 单源超时、无网络、非法响应不使整站崩溃；保留可用数据 |
| 浏览器 | 优先覆盖近期稳定版 Chrome、Edge、Safari；Firefox 核验核心浏览与存储，通知按实际支持 |
| 易用性 | 主要流程可用键盘完成；手机无主要内容横向溢出；深浅主题对比可读 |

关键验收场景：

1. 打开真实新闻，收藏并创建笔记，返回后位置不变，重开网站笔记仍在。
2. 同一来源重复刷新不产生重复条目；新快照提示后再插入。
3. 人为使一个来源失败，其余模块仍可用；失败源显示最后成功时间。
4. 视频嵌入成功时可观看；失败或受限制时能回原站。
5. 任一热榜没有数据时不显示伪造排名；原站入口不计作自动接入完成。
6. 行情缺失、休市、延迟和过期分别有正确状态，合约与单位没有混淆。
7. 笔记写入失败仍可恢复草稿；跨标签页冲突不静默覆盖。
8. 重复提醒按实例去重；重新打开网页时能看到遗漏事项。
9. 游戏可完成一局，刷新后恢复；重复刷新不重复领取离线收益。
10. 代码发布后，仓库子路径的资源、书签和刷新访问都正常。

## 17. 分期范围与完成标准

| 阶段 | 交付内容 | 完成标准 |
| --- | --- | --- |
| A：来源验证与交互样稿 | 来源能力矩阵、实际样例、今日/阅读/影院样稿 | 每个指定平台有“可接入、需账户、待验证或仅原站”结论；至少国内与国际各一真实来源通过验证 |
| B：核心信息门户 | 今日、新闻、可用热榜、财经新闻、阅读/影院、收藏与稍后读、主题、GitHub 发布流程 | 完成真实每日浏览闭环；至少一个指定平台有真实自动更新的热榜；B 站/微博/小红书逐项显示接入状态；不以演示数据交付 |
| C：个人管理 | 笔记、标签与文件夹、提醒、本地备份、恢复与搜索 | 保存与恢复可靠，通知能力边界明确，个人资料不进入公开快照 |
| D：行情与来源增强 | 分市场行情、自选、更多热榜、少量趋势历史 | A 股、美股、大宗商品分别列出实际报价覆盖与延迟；未接入市场记为暂缓，不计作行情完成；每个平台按实测能力验收 |
| E：挂机肉鸽 | 最小完整单局、构筑、永久成长、存档、离线收益 | 游戏可玩、可续档，不影响信息门户性能 |
| F：可选升级 | 云同步、后台推送、翻译摘要、历史检索 | 根据实际需要单独确定数据服务、身份权限与预算 |

可在阶段 B 后制作游戏玩法小样，完整游戏仍在主要信息体验稳定后交付。第一版发布可分为“核心先用”和“完整免费版”，不能因为游戏或某个受限接口长期阻止新闻功能上线。

如果来源验证后仍无法满足至少一个真实自动更新热榜，必须如实标记核心范围未完成并调整接入方案，不能把全部平台外链视为已满足用户的热榜需求。用户接受行情延迟，不代表可以用所有市场的原站链接代替行情模块。

不在来源验证前承诺具体完成天数。影响工作量最大的因素是热榜接入与行情许可，其次是游戏美术和玩法深度。

网站开发交付物包括：完整源码、可上传 GitHub 的目录或压缩包、一次性配置 Pages 的图文说明、构建与更新流程、来源实际接入状态清单、本地数据备份恢复说明，以及已完成和暂缓功能的验收记录。实际部署后再提供经过验证的访问地址。

## 18. 费用与维护计划

免费基线不要求购买服务器、域名、AI 服务或付费行情。使用 GitHub 默认域名，遵守其当时的使用与资源限制；新闻源账户可能仍需注册申请。

“免费优先”不是任何规模下都永久零成本。每个来源记录调用预算、采集次数、失败率和条款链接；预算不足时降低频率或切换原站入口，不自动产生付费费用。

维护工作集中在：来源格式变化、访问失败、定时任务停用、浏览器数据备份和依赖更新。设置页提供最近成功更新时间与简明维护说明。第一版不额外收集行为分析或把个人笔记上传至第三方。

若将来要求跨设备自动同步、关闭网页后提醒、秒级行情或站内完整观看受限内容，再单独评估服务与费用；这些需求不混入免费静态版的承诺。
